<h2>二、OpenClaw 记忆架构 | OpenClaw Memory Architecture</h2>
<p><strong>中文</strong></p>
<h3>2.1 核心理念：文件即记忆</h3>
<p>OpenClaw 将 Agent 的「身份」与「知识」完全外化为工作区中的 Markdown 文件。默认路径：<code>~/.openclaw/workspace/</code>。</p>
<pre><code class="language-text">~/.openclaw/workspace/
├── SOUL.md            # 人格（每次会话注入，通常人工维护）
├── AGENTS.md          # 操作手册（含记忆规则）
├── USER.md            # 用户偏好
├── MEMORY.md          # 长期记忆（Agent 可更新）
├── memory/            # 日记式记忆
│   ├── 2026-06-01.md
│   └── 2026-06-05.md
└── skills/            # 技能（与记忆分离）
    └── weather/SKILL.md
</code></pre>
<h3>2.2 系统提示词注入顺序</h3>
<p>OpenClaw 在会话启动时按固定顺序组装系统提示词：</p>
<ol>
<li><code>SOUL.md</code> — 人格优先，影响模型注意力分配</li>
<li><code>IDENTITY.md</code> — Agent 身份信息</li>
<li><code>USER.md</code> — 用户上下文</li>
<li><code>AGENTS.md</code> — 工具与流程指令</li>
<li><code>MEMORY.md</code> — 持久知识（变化最频繁，靠后注入）</li>
</ol>
<p>这种顺序设计确保人格指令优先于易变的记忆内容。</p>

<h3>2.4 记忆更新机制</h3>
<p>OpenClaw 的记忆更新依赖 <code>AGENTS.md</code> 中定义的规则。Agent 在会话中根据指令决定是否写入 <code>MEMORY.md</code> 或 <code>memory/YYYY-MM-DD.md</code>。没有内置的：</p>
<ul>
<li>自动技能生成</li>
<li>FTS5 历史检索</li>
<li>记忆容量管理与整合</li>
</ul>
<p>优势是透明、可审计；劣势是随记忆增长，系统提示词 Token 成本线性上升。</p>
<h3>2.5 会话持久化</h3>
<p>会话记录存储在 <code>~/.openclaw/agents/&lt;agent&gt;/sessions/*.jsonl</code>，用于会话连续性和可选的记忆索引，但<strong>不等于</strong>结构化记忆检索层。磁盘访问权限即信任边界。</p>
<p><strong>English</strong></p>
<h3>2.1 Core Idea: Files as Memory</h3>
<p>OpenClaw externalizes agent identity and knowledge as Markdown in the workspace. Default path: <code>~/.openclaw/workspace/</code>.</p>
<h3>2.2 System Prompt Injection Order</h3>
<p>At session start, files assemble in fixed order: SOUL.md → IDENTITY.md → USER.md → AGENTS.md → MEMORY.md. Persona instructions precede volatile memory content.</p>

<h3>2.4 Update Mechanism</h3>
<p>Updates follow rules in AGENTS.md. No built-in auto-skill generation, FTS5 history search, or capacity management. Transparent and auditable, but prompt token cost grows linearly with memory size.</p>
<h3>2.5 Session Persistence</h3>
<p>Transcripts live in <code>~/.openclaw/agents/&lt;agent&gt;/sessions/*.jsonl</code> for continuity and optional indexing — not a structured memory retrieval layer. Filesystem access is the trust boundary.</p>

<p><strong>中文</strong></p>
<h3>3.1 四层记忆模型</h3>

<h3>3.2 第一层：工作记忆</h3>
<p>当前会话中的消息、工具调用结果、压缩后的历史摘要。由 <code>ContextCompressor</code> 在上下文超阈值时进行有损压缩，触发会话分裂（<code>parent_session_id</code> 链）。</p>
<h3>3.3 第二层：会话记忆（SQLite + FTS5）</h3>
<p><strong>存储位置</strong>：<code>~/.hermes/state.db</code>（WAL 模式）</p>
<p><strong>核心表结构</strong>：</p>
<pre><code class="language-text">state.db
├── sessions          — 会话元数据、Token 统计、计费
├── messages          — 完整消息历史
├── messages_fts      — FTS5 全文索引（content + tool_name + tool_calls）
├── messages_fts_trigram — Trigram 分词器（中日韩子串搜索）
└── state_meta        — 键值元数据
</code></pre>
<p><strong>检索工具</strong>：<code>session_search</code></p>

<p><strong>冻结快照模式</strong>：会话启动时将记忆渲染进系统提示词后<strong>不再变更</strong>（保护 LLM 前缀缓存）。Agent 在会话中通过 <code>memory</code> 工具增删改，变更立即落盘，但下次会话才进入 Prompt。</p>
<p><strong>memory 工具操作</strong>：</p>
<pre><code class="language-python">memory(action="add",    target="memory", content="...")

</code></pre>
<p><strong>安全扫描</strong>：写入前检测 Prompt 注入、凭证外泄、不可见 Unicode 字符。</p>
<h3>3.5 第四层：技能记忆（程序性记忆）</h3>
<p>技能是 Hermes 闭环学习的核心产出，存储于 <code>~/.hermes/skills/</code>。</p>
<p><strong>渐进式披露（Progressive Disclosure）</strong>：</p>
<pre><code class="language-text">Level 0: skills_list()        → [{name, description}]     (~3k tokens)
Level 1: skill_view(name)     → 完整 SKILL.md 内容        (按需)
Level 2: skill_view(name, path) → 特定参考文件            (按需)
</code></pre>
<p>效果：技能库从 40 个增长到 200 个，上下文成本几乎不变。</p>
<p><strong>自动创建触发条件</strong>（<code>skill_manage</code> 工具）：</p>
<ul>
<li>完成 5+ 次工具调用的复杂任务</li>
<li>经历错误并找到正确路径</li>
<li>用户纠正了 Agent 做法</li>
<li>发现非平凡工作流</li>
</ul>
<p><strong>自改进</strong>：优先使用 <code>patch</code>（<code>old_string</code> / <code>new_string</code>）而非全量 <code>edit</code>，节省 Token。</p>

<h3>3.7 闭环学习与记忆的协同</h3>
<pre><code class="mermaid">sequenceDiagram
    participant U as 用户
    participant A as AIAgent
    participant M as Memory Manager
    participant S as Skill Store
    participant DB as SQLite FTS5

    U-&gt;&gt;A: 复杂任务请求
    A-&gt;&gt;A: 执行工具（5+ 次）
    A-&gt;&gt;M: 策划记忆（add/replace）
    A-&gt;&gt;S: skill_manage(create)
    A-&gt;&gt;DB: 持久化会话消息
    Note over A,S: 下次同类任务
    A-&gt;&gt;S: skill_view（按需加载）
    A-&gt;&gt;DB: session_search（历史召回）
    A-&gt;&gt;U: 更高效响应</code></pre>
<p><strong>English</strong></p>
<h3>3.1 Four-Layer Memory Model</h3>
<p>Working memory (current context) → Session memory (SQLite + FTS5) → Persistent memory (MEMORY.md / USER.md with char limits) → Skill memory (progressive disclosure in <code>~/.hermes/skills/</code>). Optional external providers (Honcho, Mem0, etc.) run in parallel.</p>
<h3>3.2 Layer 1: Working Memory</h3>
<p>Current session messages and tool results. <code>ContextCompressor</code> summarizes when context exceeds thresholds, triggering session splits via <code>parent_session_id</code> chains.</p>
<h3>3.3 Layer 2: Session Memory</h3>
<p>Stored in <code>~/.hermes/state.db</code> (WAL mode). FTS5 + trigram indexes for full-text and CJK substring search. <code>session_search</code> tool for on-demand recall. Write contention handled with short timeouts and jittered retries.</p>
<h3>3.4 Layer 3: Persistent Memory</h3>
<p><code>MEMORY.md</code> (~2200 chars) and <code>USER.md</code> (~1375 chars) in <code>~/.hermes/memories/</code>. <strong>Frozen snapshot</strong> at session start for prefix-cache stability. <code>memory</code> tool for add/replace/remove with security scanning.</p>
<h3>3.5 Layer 4: Skill Memory</h3>
<p>Procedural memory in <code>~/.hermes/skills/</code> with progressive disclosure (index → full content on demand). Auto-created after complex tasks; self-improved via <code>skill_manage</code> patch.</p>
<h3>3.6 External Memory Providers</h3>
<p>8 optional providers (Honcho, Mem0, OpenViking, Hindsight, etc.) complement built-in memory.</p>
<h3>3.7 Learning Loop Synergy</h3>
<p>Task completion → memory curation → skill creation → FTS5 indexing → faster recall on similar future tasks.</p>

<h2>五、最佳实践 | Best Practices</h2>
<p><strong>中文</strong></p>
<h3>OpenClaw</h3>
<ol>
<li><strong>职责分离</strong>：人格写 SOUL.md，流程写 AGENTS.md，事实写 MEMORY.md</li>
<li><strong>版本管理</strong>：SOUL.md 和 AGENTS.md 纳入 Git；MEMORY.md 可让 Agent 自管</li>
<li><strong>控制体积</strong>：MEMORY.md 定期人工审查，避免 Prompt 膨胀</li>
<li><strong>日记归档</strong>：用 <code>memory/YYYY-MM-DD.md</code> 分离当日 ephemeral 内容</li>
</ol>
<h3>Hermes Agent</h3>
<ol>
<li><strong>善用分层</strong>：关键事实放 MEMORY.md；历史细节靠 <code>session_search</code></li>
<li><strong>监控容量</strong>：MEMORY.md 超 80% 时主动整合条目</li>

<h3>OpenClaw</h3>

<li>Separate concerns: SOUL.md (persona), AGENTS.md (procedures), MEMORY.md (facts)</li>

<h2>六、结语 | Conclusion</h2>
<p><strong>中文</strong></p>
<p>OpenClaw 的记忆系统是 <strong>「透明文件柜」</strong>——简单、可读、完全由人掌控，适合重视可审计性与手动定制的用户。Hermes 的记忆系统是 <strong>「分层图书馆 + 自学习档案员」</strong>——通过 SQLite 检索、字符预算、技能渐进披露和闭环学习，在 Token 成本可控的前提下实现「越用越懂你」。选择哪套记忆架构，本质上是在 <strong>可控透明度</strong> 与 <strong>自动进化效率</strong> 之间做权衡。</p>
<p><strong>English</strong></p>
<p>OpenClaw's memory is a <strong>transparent filing cabinet</strong> — simple, readable, fully human-controlled, ideal for users who value auditability and manual curation. Hermes's memory is a <strong>layered library with a self-learning archivist</strong> — SQLite search, char budgets, progressive skill disclosure, and closed-loop learning deliver "knows you better over time" with controlled token cost. The choice is fundamentally a tradeoff between <strong>transparent control</strong> and <strong>automatic evolutionary efficiency</strong>.</p>
